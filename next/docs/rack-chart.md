# Шахматка: что было в старом клиенте и что делает `hotel-desktop`

Срез поведения снят с двух экранов, код которых не менялся:

- `Resort/wroomchart.*` и `Resort/wroomchartclasses.*` — шахматка с кнопки «Room chart».
- `Resort/wmaindesk.*` и `RoomChart/*` (`roomscene`, `reserverect`, `reservewidget`, делегаты дня и номера) — второй график. Кнопка в приветствии скрыта (`btnNewRoomChart`), но жест «протянуть дни по номеру» и кнопки прокрутки живут там.

Новый экран — вкладка «Шахматка» в `hotel-desktop`. Данные только из `GET /api/v1/rack` сессии пользователя (его `property_id`). MariaDB клиент не открывает.

Пустая сетка на предыдущей версии была из-за холста фиксированной ширины внутри `QScrollArea`: виджету задавался только `minimumSize`, фактический размер оставался нулевым, а пустые клетки без броней линиями не рисовались. Сейчас сетка рисуется на весь виджет, в том числе когда проживаний нет.

## Сделано

| Поведение старого клиента | Сейчас |
|---------------------------|--------|
| Строки — все номера, даже без брони. Порядок: корпус (`f_building`), затем номер (`f_id`). | Все `nx_room` объекта. Порядок: код корпуса (пустой первый), затем код номера (числовой, если оба кода — числа), затем id. |
| Сетка день × номер видна без броней. Выходные отмечены, номер дня и день недели в шапке, сверху название месяца. | То же. Линии клеток рисуются всегда. |
| Окно не фиксирует число дней: видно столько колонок, сколько влезает, строки занимают высоту. | Колонки и строки делят ширину и высоту виджета. Минимум колонки 28 px, строки 22 px. Сколько влезло — пересчёт в `resize`. Если номеров меньше, чем влезает по минимуму, строки растягиваются на всю высоту. |
| Кнопки влево/вправо и вверх/вниз (`WMainDesk`, шаг около 200 px). | Влево/вправо на один день (кнопка с автоповтором и стрелки клавиатуры). Вверх/вниз на один номер, только когда номера не влезают; иначе кнопки выключены. |
| Кнопки категорий (`f_room_classes`, у `WMainDesk` одна категория, у `WRoomChart` несколько) применяются сразу. Отдельно корпус, этаж в данных номера есть. | Кнопки типа номера, корпуса и этажа. Несколько кнопок в одной группе — «или», группы между собой — «и». Пустой набор в группе не фильтрует. Сеть не дёргается. «Все» снимает кнопки. |
| Поле перехода к номеру (`leJumpToRoom`). | Поле «Номер»: подстрока кода, сразу. |
| Цвет ячейки номера по состоянию (свободен / заезд / грязный / ремонт). | Цвет подписи номера по `status_code`: готов, занят, грязный, ремонт, служебный, комплиментарный, выведен из фонда. Фильтр состояния — список рядом с полем номера, сразу. |
| Полоса брони цветом по состоянию (бронь, заезд, ремонт, вывод), точка по подтверждению (подтверждена, гарантирована, предварительная, блок). | То же по `state_code` и `reservation_status`. |
| Подсказка: гость, даты, номер. | Подсказка на полосе (гость, даты, состояние, статус брони) и на подписи номера (тип, корпус, этаж, состояние). |
| Клик по брони — карточка, двойной клик — окно брони или счёт, если уже заезд. | Клик и двойной клик открывают ту же карточку брони. Отдельного счёта нет. |
| Протягивание пустых дней по строке номера открывает черновик с датами (`ChartScene` / `RoomScene` → диалог). | Отпускание кнопки сразу открывает «Новая бронь» с этим номером, заездом и выездом (выезд — утро после последней выбранной ночи). |
| Контекстное меню / док: открыть бронь. | Правый клик: «Открыть бронь» или «Новая бронь» на эту ночь. |
| Сегодня: график прокручивается к рабочей дате. | Колонка сегодня подсвечена. Кнопка «Сегодня» ставит первый видимый день на сегодня. |
| Живое обновление через кэш и UDP. | Кадры WebSocket `reservation.*` и `room.status_changed` заново читают `GET /api/v1/rack`, не сбрасывая день и фильтр. |

Сервер по-прежнему отдаёт окно не длиннее 120 ночей. Клиент запрашивает видимые дни плюс запас и подгружает следующее окно, когда прокрутка выходит за уже загруженное. Отменённые проживания и брони в ответ не входят.

## Отложено

| Поведение старого клиента | Почему не сейчас |
|---------------------------|------------------|
| Перетаскивание полосы на другой день или номер с записью в базу. В старом коде `Reserve::mouseMoveEvent` рисует сдвиг, `resetPos` возвращает полосу на место. Ctrl+перетаскивание в `ChartScene` только начинает новый черновик. | Сохранённого переноса нет и в легаси. Новый черновик закрывается выделением пустых дней. |
| Изменение длины полосы мышью. | В легаси ширина считается из дат, отдельного ресайза с записью нет. Даты меняются в карточке брони. |
| Двойной клик по заезду открывает счёт (`WInvoice`), кнопка группы, конец дня. | Фолио и конец дня в `hotel-api` ещё не открыты. |
| Фильтры кровати, курения и кардекса (`f_room_bed`, smoke, cardex). | В `nx_room` этих полей нет. Отдельная миграция, не эта задача. |
| Фильтр полос по статусу брони и поиск гостя в доке (`DWMainDeskHint`). | Список броней уже ищет гостя. На шахматке оставлены фильтры номеров. |
| Диалог цветов полос (`dlgchartcolor`) и черновики service / out of order как отдельные виджеты. | Цвета заданы в коде по `state_code`. Отдельного состояния «service» в `nx_stay` нет. |
| Холст на пять лет вперёд одним куском. | Окно API — 120 ночей; дальше клиент листает днями. Так сетка заполняет экран, а не уезжает в полосу прокрутки фиксированной ширины. |
| Синхронные три `QGraphicsView` (номера, даты, тело). | Шапка и номера рисуются в том же виджете, отдельно их прокручивать не нужно. |

Новых миграций нет: хватает `0002`–`0004`. Поля `type_id`, `type_code`, `building_id`, `building_code` добавлены в JSON `GET /api/v1/rack` (контракт `0.9.0`).
