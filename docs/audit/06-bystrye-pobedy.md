# 6. Быстрые победы

Пункты ниже не требуют нового backend и не меняют правила кассы. Их можно делать до фазы 2 и параллельно с ней. Пароли в этот текст не переписываются — только места, где они лежат.

## 1. Ротация секретов и чистка дерева

Сменить на сервере пароль, опубликованный в git, завести пользователю приложения права только на базу отеля, раздать станциям новый профиль.

Удалить или вычистить:

- `smarthotel/conf.php` — креды в открытом виде;
- константы подключения в `Resort/dlgtracking.cpp` (~строка 113) и `Tester/mainwindow.cpp` (~строки 59–63);
- `cards/*.jpeg` — посторонние скриншоты;
- `smarthotel/.idea/`;
- данные из `DB/db.sql` (гости, пользователи, пароли ККМ). В репозитории оставить DDL.

Добавить в `.gitignore`: `*.sql` дампы с данными, `.idea/`.

**Ценность.** Закрывает S0 без касания фолио.

## 2. Перестать раздавать пароль по UDP

В `Server/dlgmain.cpp` ответ на `"who"` (~строки 240–256) содержит `username`, `password`, `loguser`, `logpass`. Пока сервис обнаружения ещё нужен установщику, ответ должен содержать только адрес API или host без секрета. Пароль установщик вводит руками. Если `Server` на объекте не запущен (проект и так не собирается: нет `command.h`), достаточно убедиться, что старый exe не висит в сети, и закрыть порт.

## 3. Убрать из сборки пустое

- `Cache2/cache2.*` и строки в `Resort/sources.cmake`.
- Несуществующий `../Selector` в `Resort/CMakeLists.txt`.
- Порт `Server2` не выкидывать в той же пачке: `MainWindow` реально слушает 2134, хотя данные никто не читает. Закрытие порта — отдельный коммит после проверки сети (раздел 4 документа про мусор).

Сборка становится честнее, дифф крошечный.

## 4. Скрипт целостности только на чтение

Один SQL-файл в `docs/audit/sql/` или в будущем `backend/`, который на копии базы печатает:

- брони с `f_guest`, которого нет в `f_guests`;
- брони с `f_room`, которого нет;
- пересечение активных броней по одному `f_room` и пересекающимся датам (`f_state` in check-in/reserved);
- `m_register.f_res`, которого нет в `f_reservation`;
- дубли `m_vaucher.f_code` (`RR`, `CM`);
- дубли `users.f_username`;
- строки `users_rights` с повтором `(f_group, f_right)`.

Ничего не чинить автоматическим DELETE. Список — вход в фазу 1 и аргумент, почему FK нельзя включить завтра.

## 5. Уникальные индексы там, где дублей нет

Если скрипт из пункта 4 показал ноль дублей логина и ноль дублей кода ваучера после ручной чистки справочника:

- `UNIQUE` на `users.f_username`;
- `UNIQUE` на `m_vaucher.f_code`.

Это дешёвая защита от следующих дублей. Если дубли есть — сначала данные, потом индекс. На большие таблицы (`m_register`, `f_reservation`) в этой пачке индексы не добавлять.

## 6. Перестать убивать процесс при сбое номера документа

В `Base/baseuid.cpp` при ошибке генератора вызывается `exit(0)`. Заменить на возврат ошибки в диалог («не удалось выдать номер, повторите»), процесс кассы остаётся живым. Поведение удачного пути не меняется. Строковую склейку SQL в этом же файле (`.arg(prefix)`, `ap(prefix)`) перевести на уже существующие bind-параметры `DoubleDatabase` — правка локальная.

## 7. Закрыть самые прямые склейки SQL

Не кампания «все 800 exec», а места, куда попадает текст с экрана:

| Файл | Что сделать |
|------|-------------|
| `Resort/dlgclearlog.cpp` | имя пользователя в запрос через bind, не конкатенация |
| `Resort/wreservationroomtab.cpp` | `delete` по id брони через bind |
| `Base/stringutils.h` макрос `ap()` | не использовать для новых запросов; в точках пункта 6 заменить |

`serv_reports.f_sql` в этой пачке не переписывать: это уже фаза 7. Достаточно на уровне процесса запретить править `f_sql` всем, кроме одной группы, если матрица прав это позволяет без разработки.

## 8. Снять мёртвый веб, не начиная новый

`smarthotel/` не является PMS. Пока каталог лежит на виртуальном хосте с `root`, это вход. Снять сайт. Код удалить после смены пароля, чтобы никто не задеплоил папку обратно.

Попутно не чинить `f_lastname` в `user.php`: чинить нечего, экран пустой.

## 9. Одна пара фильтров вместо двух пунктов меню

`fexpectedarrivals` и `fexpectedarrivals2` оба подключены. Оставить вариант с двойным кликом в бронь, второй пункт меню убрать после сравнения двух выборок за один день на копии. То же для `fcitytrayledger` / `fcitytrayledger2`, если SQL эквивалентен. Если не эквивалентен — не сливать, записать разницу в протокол фазы 1.

## 10. Имена, которые мешают каждый день

Переименовать файлы без смены логики: `dlggroupreservationfuck` → `dlggroupreservation`, поправить `sources.cmake` / `.pro` и include. Отдельный коммит. Касса не участвует.

Имеет смысл в тот же заход завести нормальный `README.md`: как собрать десктоп, где база, что `Server` не является API, ссылка на `docs/audit/`. Текущий README — две строки changelog версии `1.8.19.787`.

## 11. Журнал подключений к MariaDB

Включить `general_log` на короткий срок или аудит входов и посмотреть, какие хосты логинятся. Это список станций и забытых скриптов перед любым `REVOKE`. Дешёвая разведка для фазы 10, сделать её в фазе 0.

## 12. Не делать вид, что это тоже «быстро»

Следующее выглядит маленьким и ломает бой:

- включить FK на `f_reservation` и `m_register`;
- переименовать `m_vaucher` или колонку `f_invoice`;
- выкинуть `wreportssetold`, не проверив меню;
- перевести конец дня на новый код без прогона на копии;
- править MD5 на bcrypt в SQL так, чтобы старый десктоп перестал входить (смена хеша — только в сервисе, с приёмом старого хеша один раз, фаза 2).
