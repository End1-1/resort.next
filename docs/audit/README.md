# Аудит архитектуры SmartHotel (PMS)

Дата обзора: 2026-10-05. Снимок кода: ветка `main`, версия клиента из `README.md` — `1.8.19.787`.

Это независимый разбор репозитория гостиничной PMS, которая уже работает в эксплуатации. Код приложения в этом изменении не трогался. Цель — назвать реальные проблемы и дать поэтапный план, после которого:

- клиенты (текущий десктоп и будущий веб) не ходят в базу напрямую;
- один backend на вебе владеет правилами и данными;
- схема приведена к нормальному виду без остановки отеля;
- мёртвый код и секреты убраны.

## Главный вывод

Система — толстый клиент Qt/C++. Почти вся операционная логика (бронь, фолио, касса, конец дня, фискализация) живёт в виджетах и пишет SQL в MariaDB через `DoubleDatabase`. Отдельного прикладного сервера, через который проходят проводки, в репозитории нет. Отчёты частично сидят в 21 хранимой процедуре и в тексте `serv_reports.f_sql`, который клиент исполняет как есть.

Переписывать продукт одним большим куском не стоит: денежный контур без тестов, фискальные аппараты и шахматка завязаны на неявные правила в файлах по 60–90 КБ. Рабочий путь — strangler fig: новый HTTP API становится единственной дверью в базу, десктоп переводится на него модуль за модулем, схема нормализуется уже за этой дверью.

Самый чистый кусок кода сегодня — интеграция Excely (`excely/`, слои DTO → черновик брони → запись в БД). Новый backend стоит строить в том же духе: контракт отдельно, SQL отдельно, UI отдельно.
