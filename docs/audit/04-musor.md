# 4. Что удалить и что слить

Правило: сначала перестать поставлять мёртвое и опасное, потом сливать дубли, и только в конце выкидывать живые экраны, когда их сценарий есть в API. Удаление `winvoice.cpp` «потому что большой» — не пункт этого списка.

Пометки: **сейчас** — можно убрать отдельным коммитом, не меняя поведение смены; **после сверки** — на объекте проверить, что пункт не используется; **после API** — вместе с переносом модуля.

## 4.1. Секреты и не-исходники — сейчас

| Путь | Почему | Действие |
|------|--------|----------|
| `smarthotel/conf.php` | Host, `root` и пароль БД в git | Сменить пароль на сервере, убрать файл из истории, не коммитить креды снова |
| `Resort/dlgtracking.cpp` около строки 113 | Зашитые host `10.1.0.33`, пользователь `root`, пароль, база `testb` | Удалить ветку с константами; экран аудита пусть берёт профиль соединения |
| `Tester/mainwindow.cpp` около строк 59–63 | Host `10.1.0.2` и пароль | Тестер читает переменные окружения |
| `DB/db.sql` | Дамп с гостями, бронями, MD5 пользователей, паролями ККМ в `serv_tax` / `s_tax_map` | Заменить в git на DDL без данных. Боевой дамп хранить вне репозитория |
| `cards/*.jpeg` | Скриншоты WhatsApp экрана выгрузки в бухгалтерию, не ресурсы приложения | Удалить из дерева и из истории |
| `smarthotel/.idea/` | Личный проект PhpStorm, словарь Administrator | Удалить, добавить `.idea/` в `.gitignore` |

Смена пароля на сервере обязательна даже после удаления файла: он уже в истории git.

| `Server2/` | `DataHandler` пустой. При этом `MainWindow` держит `Listener`, и конструктор слушает `0.0.0.0:2134`. Сигнал `callHandler` нигде не подключён | Удаление члена из `MainWindow` закрывает порт. Это уже поведение станции, не мёртвый файл «в стороне». | Пара | Что различается | Куда свести |

| `Filter/fexpectedarrivals.cpp` и `fexpectedarrivals2.cpp` | Вторая версия открывает бронь по двойному клику; обе в меню | Оставить поведение v2, убрать пункт меню v1 |

| Файл | Во что |
|------|--------|
| `Resort/dlggroupreservationfuck.*` | `dlggroupreservation` — экран боевой, имя мешает поиску и ревью |

Опечатки схемы (`m_vaucher`, `s_settigns_values`, `Chekout`, `f_donotdisturbe`) не чинить ALTER-ом на бою. Новые таблицы называются правильно, старые доживают view (документ 2).

## 4.4. Каталог `smarthotel/` — после сверки, практически сейчас

PHP-приложение не содержит экрана брони: `index.php` проверяет `web_sessions` и рисует header/footer. `welcome.php` пустой. `user.php` ломается на регистре имён колонок и клеит `"FUCK"` в ошибку SQL.

Действие: снять каталог с боевого виртуального хоста, чтобы пароль из `conf.php` перестал быть точкой входа, затем удалить код, когда появится настоящий веб на API. Не дописывать PMS на этих файлах.

## 4.5. После появления API — крупное удаление

Удалять только когда сценарий покрыт сервером и станции обновлены:

- Прямые `exec` в переведённом модуле и глобальные `__dd1Password` из этого пути.
- `hotel_cache_update` для переведённых кэшей.
- Клиентское исполнение `serv_reports.f_sql` (`Filter/fcommonfilterbydate.cpp`, `Resort/tablemodel.cpp`).
- Процедуры аналитики — по одной, когда отчёт с тем же итогом есть на сервере.
- Compat-write в старые таблицы и затем сами `f_reservation_retired` / `m_register_retired`.
- `Server/` UDP, если обнаружение базы заменено URL.
- Встроенный генератор с `exit(0)` в `Base/baseuid.cpp` на клиенте.
- Пустые и временные таблицы: `m_temp_advance`, `o_temp_disc`, `id_back`, `airwicktravelline`, заглушка `guests` — после проверки, что за последний рабочий месяц в них нет новых строк.

## 4.6. Не удалять

| Что | Почему |
|-----|--------|
| `excely/` | Рабочая интеграция и единственный аккуратный слой. Переносится в сервис, не в мусор |
| `ATS/` | Живой разбор АТС. Станет локальным шлюзом |
| `Print/`, печать ваучеров | Юридически значимые формы. Менять движок печати отдельно от переноса проводок |
| `Vouchers/` и коды AV/RM/CO | Язык кассы. Сохраняются как коды `posting` |
| `Filter/*`, которые есть в меню и в `serv_reports` | Это продукт, не мусор, пока отчёт не воспроизведён |
| `Updater/`, `setup/` | Канал поставки десктопа ещё нужен |
| Кэши `Cache/cache*.cpp` | Умрут естественно, когда справочник читается из API; до этого ими пользуется шахматка |

## 4.7. Порядок уборки, чтобы не смешать с миграцией

1. Ротация секретов и чистка git (раздел 4.1) — не зависит ни от чего.
2. Удаление `Cache2`, битого include `Selector`, скринов, `.idea`.
3. Слияние пар фильтров, которые оба в меню, с проверкой на копии базы: цифры отчёта до и после совпали.
4. Всё, что связано с проводками и схемой, — только по фазам документа 5.
